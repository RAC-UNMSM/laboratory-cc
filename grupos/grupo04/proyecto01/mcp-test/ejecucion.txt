GUÍA DE EJECUCIÓN — MCP GRUPO04 (DOCKER)
==========================================

Carpeta del proyecto:
C:\Users\User\Desktop\laboratory-cc-grupo04\grupos\grupo04\proyecto01\mcp-test

El único modo incluido en este proyecto es Docker Compose. El contenedor inicia
server.py, atiende MCP en el puerto interno 8000 y conserva los PDFs en
SeaweedFS. app.py, host.exe y config.yml fueron retirados: el túnel personal de
Cloudflare no forma parte de este flujo.

1. REQUISITOS Y PREPARACIÓN
---------------------------

1) Inicia Docker Desktop y espera a que indique que Docker está ejecutándose.
2) Abre PowerShell y entra a la carpeta:

    cd C:\Users\User\Desktop\laboratory-cc-grupo04\grupos\grupo04\proyecto01\mcp-test

3) Define el nombre exacto del contenedor en esa ventana:

    $env:LAB_CONTAINER_NAME = "lab-grupo04_proyecto01_mcp-test"

La variable dura solo en esa ventana de PowerShell. Si abres otra, asígnala de
nuevo antes de usar Docker Compose.

4) Comprueba la red externa que utiliza el laboratorio:

    docker network inspect lab_net

Si Docker indica que no existe, créala una sola vez:

    docker network create lab_net

Crear lab_net solo crea la red; no inicia SeaweedFS. Para probar PDF localmente, SeaweedFS también debe estar activo y conectado a esa red. Si no lo tienes disponible, ejecuta las tools con include_report=false; el cálculo funciona, pero no habrá PDF.

2. CONSTRUIR Y LEVANTAR EL MCP
------------------------------

En la ventana de PowerShell ubicada en mcp-test, ejecuta:

    docker compose up --build

Deja esa ventana abierta mientras uses el MCP. La primera construcción puede
demorar porque Docker instala las dependencias Python. Cuando esté listo debes
ver una línea similar a:

    Uvicorn running on http://0.0.0.0:8000

El 8000 es el puerto dentro del contenedor. Compose lo publica en un puerto
libre del equipo para evitar conflictos con Python, Docker Desktop u otros
servicios que ya ocupen el 8000.

Abre una segunda ventana de PowerShell, entra a la misma carpeta y consulta el
puerto de Windows:

    cd C:\Users\User\Desktop\laboratory-cc-grupo04\grupos\grupo04\proyecto01\mcp-test
    docker compose port mcp-test 8000

Ejemplo de salida:

    0.0.0.0:49153

En este ejemplo, el puerto que debes usar es 49153. El número real puede ser
distinto en tu equipo o después de volver a crear el contenedor.

3. ABRIR MCP INSPECTOR
----------------------

En una tercera ventana de PowerShell ejecuta:

    npx @modelcontextprotocol/inspector@latest

Si npm pregunta si puede instalar el Inspector, responde y. Espera el mensaje
MCP Inspector Web is up and running. Si no abre el navegador automáticamente,
copia en él la dirección local que imprime la terminal, normalmente comienza
con http://127.0.0.1:6274/. Mantén abierta esa terminal mientras uses Inspector.
No compartas la URL completa que incluye MCP_INSPECTOR_API_TOKEN.

En MCP Inspector:

1) Abre Servers y elige Add Servers > Streamable HTTP.
2) Escribe un nombre, por ejemplo grupo04-docker.
3) En URL, escribe http://127.0.0.1:49153/mcp, reemplazando 49153 por el
   puerto que devolvió docker compose port.
4) Deja la autenticación vacía mientras el servidor siga sin autenticación.
5) Conecta, abre Tools y confirma que aparecen las herramientas.

La dirección /mcp no es una página web normal. Si la abres directamente en el
navegador, es normal recibir Missing session ID o Bad Request. Usa Inspector
para iniciar la sesión MCP.

4. PROBAR UNA HERRAMIENTA
-------------------------

En Servers selecciona la conexión grupo04-docker, luego abre Tools. Selecciona
una herramienta, revisa sus argumentos y ejecuta un caso. Por ejemplo, en
interpolacion_lagrange activa Edit as JSON y pega:

    {
      "points": [
        {"x": 0, "y": 1},
        {"x": 1, "y": 2},
        {"x": 2, "y": 5}
      ],
      "x_eval": 1.5,
      "level": "inicial",
      "include_report": false
    }

El resultado esperado es P(x)=x^2+1 y P(1.5)=3.25. include_report=false evita
crear un PDF para esta llamada.

5. PROBAR LOS PDF Y SEAWEEDFS
-----------------------------

Las herramientas intentan generar PDF por defecto. Esto requiere que SeaweedFS esté disponible y unido a lab_net; crear la red por sí sola no basta. Sin SeaweedFS, el cálculo numérico sigue disponible con include_report=false, pero la subida del informe fallará. Cuando storage sí esté disponible, busca en la respuesta:

    report.preview_url
    report.download_url

SeaweedFS debe estar disponible dentro de lab_net. El bucket de esta app es
grupo04-mcp-test-imgs. La generación del PDF ocurre en memoria, se sube al
bucket y las rutas /reports/<archivo>/preview y /reports/<archivo>/download
lo recuperan desde allí.

En Docker local, Compose puede asignar un puerto de Windows aleatorio. Si
preview_url o download_url apunta a localhost:8000, reemplaza solo el host y
puerto por 127.0.0.1:<puerto-asignado>, manteniendo el resto de la ruta.

En producción, el despliegue proporciona LAB_DOMAIN y LAB_PUBLIC_PATH y Caddy
debe enviar las rutas de la app, incluyendo /mcp y /reports, al contenedor.
La publicación pública del laboratorio la administra infraestructura; no se
inicia host.exe ni un túnel desde esta carpeta.

6. DETENER Y REINICIAR
----------------------

Para detener el servidor, vuelve a la ventana donde corre docker compose up y
pulsa Ctrl+C. Después puedes eliminar el contenedor con:

    docker compose down

Para iniciar otra vez, define LAB_CONTAINER_NAME en esa ventana y ejecuta:

    docker compose up --build

Los PDF nuevos viven en SeaweedFS y permanecen allí al recrear el contenedor.

7. COMANDOS DE DIAGNÓSTICO
--------------------------

Estado de los servicios:

    docker compose ps

Puerto de Windows publicado para MCP:

    docker compose port mcp-test 8000

Registros recientes:

    docker compose logs --since 5m --timestamps mcp-test

Registros por nombre de contenedor:

    docker logs --since 10m --timestamps lab-grupo04_proyecto01_mcp-test

Uso de memoria:

    docker stats --no-stream lab-grupo04_proyecto01_mcp-test

Estado OOM, código de salida y reinicios:

    docker inspect --format 'OOMKilled={{.State.OOMKilled}} ExitCode={{.State.ExitCode}} Restarts={{.RestartCount}}' lab-grupo04_proyecto01_mcp-test

Comprobar que la red externa existe:

    docker network inspect lab_net

8. MENSAJES QUE PUEDEN SER NORMALES
-----------------------------------

- GET /mcp con 400 o Missing session ID al abrirlo directamente en un
  navegador: el endpoint espera el protocolo y una sesión MCP; usa Inspector.
- unknown or expired session ID después de reconstruir/reiniciar: Inspector
  conserva una sesión anterior; desconecta y vuelve a conectar.
- Connection refused: el contenedor no está activo o se usó un puerto distinto
  al mostrado por docker compose port.
- Error al generar PDF o HTTP 502 en /reports: revisa que SeaweedFS esté
  conectado a lab_net y que acepte el bucket grupo04-mcp-test-imgs.
- Error de interpolación o valor —: revisa la entrada y la pestaña de
  resultados; el informe PDF es independiente del cálculo numérico.
